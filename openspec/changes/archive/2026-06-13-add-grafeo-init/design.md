# Design: add-grafeo-init

## Context

The v1.9 CLI (`generate`/`db push`/`db seed`) READS `grafeo.config.ts` but offers no way to CREATE it — every project's first step is hand-writing the config and learning the conventions. The CLI already has the building blocks `init` needs: a typed `GrafeoConfig` + `defineConfig`, a `CliIO` boundary with an `interactive` flag and a `confirm` prompt, and a generated-types header marker (`Generated by grafeo-ogm generateTypes()`) that uniquely identifies grafeo output. `init` is plumbing over these — it discovers, confirms, and writes; it introduces no new compilation logic.

## Goals / Non-Goals

**Goals:**
- `npx grafeo init` produces a working `grafeo.config.ts` with minimal input.
- Existing grafeo projects are auto-wired: detect schema + generated types + config, pre-fill paths.
- Greenfield projects get a sensible scaffold (config + starter schema + optional seed).
- Interactive by default; fully non-interactive (`--yes`/flags) for CI/scripts.
- Never destroy existing files without explicit consent.

**Non-Goals:**
- A branded TUI / logo animation. Desirable as first-run delight, but a separate, optional, TTY-only layer — out of scope here so the functional core ships first.
- Installing dependencies or running codegen as part of `init` (it prints the next step: `npx grafeo generate`).
- Prompting for or storing secrets — connection is via `NEO4J_*` env, matching the CLI's `--password` policy.

## Decisions

1. **Detection is shallow and convention-first.** Scan the working directory and a small set of common roots (`.`, `src`, `graphql`, `schema`) to a shallow depth, excluding `node_modules`/`dist`/`.git`. Identify the SCHEMA by grafeo directives (`@node`/`@relationship`) inside `.graphql`/`.gql` files — not by filename alone, so a non-grafeo GraphQL file isn't mistaken for the schema. Identify the GENERATED TYPES file by the generator's header marker, which is unambiguous. Multiple schema candidates → prompt; zero → new-project flow.

2. **Reuse the CLI's IO seam — no new dependency.** Prompts go through `node:readline/promises` (already used by the `db push` consent gate); detection and writes flow through `CliIO` so the command is unit-testable with a fake IO and temp dirs, exactly like the other commands. No TUI framework.

3. **Non-destructive by default, `--force` to overwrite.** An existing `grafeo.config.*`/`schema.graphql` is reported and preserved; overwriting requires interactive confirmation or `--force`. Mirrors the `db push --force-drop` + `--yes` consent model.

4. **Connection via env, never prompted.** The generated config's `database` block references `process.env.NEO4J_*`. `init` may write a `.env.example`, but never prompts for or persists a password.

5. **Interactive ↔ non-interactive parity.** Every prompt has a flag/default so `--yes` yields a deterministic, CI-safe run. `io.interactive === false` + no `--yes` + a required overwrite → exit non-zero with guidance (consistent with `db push` blocked-consent).

6. **`init` wires an npm `generate` script.** When a `package.json` is present, `init` adds `"generate": "grafeo generate"` to its `scripts` so codegen is one `npm run generate` away. Non-destructive: if a `generate` script already exists it is left untouched and reported (not clobbered).

7. **Greenfield starter = the Neo4j movie graph.** The scaffolded `schema.graphql` is the classic Neo4j movie example expressed in grafeo SDL — `Movie` and `Person` with `ACTED_IN`/`DIRECTED` relationships in both directions. Minimal, instantly recognizable to Neo4j users, and it exercises relationship arity/direction so the generated types are immediately interesting.

## Risks / Trade-offs

- [Mis-detecting the schema] → Directive-based detection + prompting on ambiguity avoids wiring the wrong file; a `.graphql` without grafeo directives is ignored, not assumed.
- [Filesystem scan cost / scanning the wrong tree] → Shallow depth + excluded dirs keep it fast; the search roots are conventional.
- [Clobbering user files] → Non-destructive default + `--force` gate; re-runnable safely.
- [Scope creep into a TUI] → Explicitly deferred; the animated splash is a later, optional, TTY-gated layer on top of this functional core.

## Migration Plan

Purely additive — a new command, no changes to existing CLI behavior or library APIs. README quickstart switches to `npx grafeo init` as step 1; the manual-config path remains documented.
